# MONDAY — LifeOps AI

**Live demo:** <https://lifeops-ai-sigma.vercel.app> ("Try the live demo" signs you in without an
account; demo inbox and calendar, Cloudflare Workers AI on its free daily allowance). How it is
hosted: [VERCEL_DEPLOYMENT.md](VERCEL_DEPLOYMENT.md).

**Also on GitHub Pages:** <https://gopalinternship-unibasel.github.io/lifeops-ai/> (the same app and
data; the pages are static files on GitHub Pages and the server code runs in a Supabase Edge
Function). How it works: [PAGES_DEPLOYMENT.md](PAGES_DEPLOYMENT.md).

MONDAY is a TanStack Start full-stack application (the July 2026 rework of the Bobathon LifeOps AI
project) combining:

- Supabase authentication, row-level security, and application storage
- A Google OAuth connector for Gmail and Google Calendar (with a built-in demo inbox and calendar). The
  connector was tested against mocked Google APIs, and the hosted demo has no Google OAuth client, so it
  uses the sample inbox and calendar. MONDAY has no send path: replies are saved as drafts only.
- An OpenAI-compatible LLM for planning and prioritisation: local Ollama by default on a local run, or
  the original Hugging Face router (`meta-llama/Llama-3.1-8B-Instruct`), OpenAI or Gemini; the hosted
  demo uses Cloudflare Workers AI, and a hosted site without an AI provider says the assistant is not
  set up instead of trying a local model
- A FastAPI planner service (`fastapi-backend/`) behind the productivity dashboard
- A React/Tailwind workspace for inbox, calendar, weekly planning, dashboard and profile management

## Run it locally

**Read [`RUNNING.md`](RUNNING.md).** It is the tested local setup: local Supabase in Docker (project id
`lifeops`, ports 55320-55329, all migrations in `supabase/migrations`), the FastAPI planner on
http://127.0.0.1:8010, the web app on http://localhost:5190 and the AI model in a local Ollama
(http://localhost:11434/v1). One script starts everything and writes the env files for you:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start-lifeops.ps1   # first run also installs packages
powershell -ExecutionPolicy Bypass -File scripts\stop-lifeops.ps1    # stops it again (data is kept)
```

Do not copy `.env.example` to `.env.local` for local work: its Supabase values are placeholders for
a hosted project. `scripts/write-local-env.mjs` (run by the start script) writes `.env.local` and
`fastapi-backend/.env` from `supabase status`, with local keys only. `RUNNING.md` also covers the
test user, what to try, switching the AI provider, the tests, and connecting real Gmail and Google
Calendar (needs an OAuth client of your own).

Checks:

```bash
npm test            # unit tests (vitest)
npm run check       # lint, typecheck, unit tests and build
```

## Hosted deployment

`.env.example` documents every variable for a hosted deployment. The browser and server use the same
Supabase URL and publishable-key values under different variable names:

```text
VITE_SUPABASE_URL == SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY == SUPABASE_PUBLISHABLE_KEY
```

Only `VITE_` variables are exposed to browser code. `SUPABASE_SECRET_KEY`, the Google secrets, the
LLM API key and `LIFEOPS_BACKEND_TOKEN` must remain server-only. Commit the `package-lock.json`
generated by `npm install`; never commit `.env.local`.

There are two hosted editions of the same code: `VERCEL_DEPLOYMENT.md` (Vercel: web app and planner)
and `PAGES_DEPLOYMENT.md` (GitHub Pages plus the Supabase Edge Function `lifeops-api`, which calls the
same planner). `AUDIT_2026-07-23.md` is the July 2026 review.
