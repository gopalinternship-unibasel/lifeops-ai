# MONDAY audit — 23 July 2026

## Verdict

The reviewed source is structurally suitable for a TanStack Start deployment on Vercel and is materially safer and more reliable than the uploaded revision. The project uses the current Lovable TanStack configuration required for Vercel's automatic framework handling.

No source audit can honestly guarantee that every external integration will work until the application is installed, built, migrated, configured with real credentials, and exercised against Supabase, Google, Hugging Face, and Vercel. The production gate remains `npm run check` plus the end-to-end checklist in `VERCEL_DEPLOYMENT.md`.

## Corrections made in this review

- Moved client-callable `createServerFn` wrappers from the protected `src/server/` directory to `src/functions/`, resolving TanStack Start production import-protection failures.
- Updated all route and component imports to use the new `@/functions/*` entry points.
- Replaced all deprecated `.inputValidator()` calls with `.validator()`.
- Moved the Google Fonts CSS import ahead of non-import at-rules, resolving the CSS optimizer warning.
- Added demo-calendar create, update, and delete behavior when Google is not connected.
- Added demo-calendar support when approving weekly plans.
- Made demo seed events and calendar boundaries use the browser-provided IANA time zone instead of the Vercel server time zone.
- Fixed range queries so events overlapping a range are included even when they start before the range.
- Added date-time, duration, same-day, and overlap validation for calendar and weekly-plan edits.
- Added validation and server-side filtering for AI-proposed calendar events and changes.
- Made calendar-dependent AI actions fail closed when the live calendar cannot be read.
- Added duplicate protection when weekly-plan events are approved more than once.
- Added a direct Gmail-draft save function so user-edited text is saved verbatim rather than regenerated by AI.
- Limited concurrent Gmail message reads and capped message counts.
- Added timeouts for Google OAuth, Gmail, Calendar, and Hugging Face requests.
- Revokes the Google token on explicit disconnect when Google's endpoint is available, then always removes local credentials.
- Added prompt-injection boundaries around untrusted email, calendar, task, profile, and prior-output context.
- Made database read/write failures surface instead of silently continuing in chat, profile, OAuth, plan, and calendar paths.
- Redirected new Supabase Google sign-ins through profile onboarding; returning users with a complete profile still proceed directly to the app.
- Added support for Supabase's current `SUPABASE_SECRET_KEY`, retaining the legacy service-role variable only as a fallback.
- Updated the Vercel deployment instructions and environment-variable matrix.

## Validation limitation

A dependency-aware `npm install`, ESLint run, full TypeScript typecheck, and production bundle could not be completed in the audit environment. Its npm registry gateway returned HTTP 503 and the direct npm registry was unreachable. The uploaded archive also did not contain a lockfile.

Before deployment, use Node 22 in the project directory:

```bash
npm install
npm run format
npm run check
```

Commit the generated `package-lock.json`. Do not deploy to production when `npm run check` fails.
